# 公众号图文排版 v1.1.2

把用户的稿子和截图，做成能直接粘进公众号后台的图文。

**开工前先读 [专家守则](references/专家守则.md)**：分线、每条回复的格式、什么时候停、硬规矩、出问题怎么办。守则和本文件冲突时，以守则为准。

## 分工

- **你负责判断和写**：走哪种用法、哪段是步骤、哪张图配哪一步、哪句当金句、每段标哪几个关键词；需要写稿时照用户的口吻写。
- **脚本负责长相**：`scripts/render.py` 按主题出图文。颜色、间距、公众号的格式限制全在脚本里。**不要自己手写排版代码**，手写的粘进去十有八九会掉格式。
- **脚本负责检查**：排完自动查一遍，“必须改”清零才交付。

下面的脚本都在**本技能目录的 scripts 文件夹**里，运行时写完整路径；Windows 上把 `python3` 换成 `python`。脚本只用 Python 自带的东西，不用装；装了 Pillow 会顺手压缩截图，装了 playwright 能把缩略图截成图片。

## 先分用法

| 用户给的 | 走哪种 |
|---|---|
| 一篇写完的稿子（有没有截图都行） | **只排版**：不改原文，只加排版标记 |
| 截图，加几句要讲的、一个提纲、一段语音转的文字，或者只有一个话题 | **写稿再排**：先照 `references/writing.md` 写成完整文章，再排版 |

分不清就问一句：“这篇是照原文排，还是我帮你写成完整文章？”

**两种都只停一次：排版之前，先让用户看六套缩略图选主题，选好再排。** 要用户拍板的事（选主题、核对稿子、截图对不上的、要不要加署名）全放进这一条消息。用户已经点名主题，或者说“你定”“直接排”，才不停。

## 流程

### 1. 收东西、读设置

- 在用户的工作文件夹里做（用户没指定，就在当前文件夹建一个以文章标题命名的文件夹）。
- 读设置：先读本技能的 `settings.md`，再读工作文件夹里的「公众号设置.md」（有就以它为准）。
- 没有「公众号设置.md」时，在选主题那条消息里顺便问一句署名和栏目；用户给了，就照 `settings.md` 的格式建「公众号设置.md」，以后不再问。

### 2. 截图对位（有截图时）

照 `references/screenshots.md`：截图按出现顺序改名放进工作文件夹的 `截图` 文件夹，每张配一句说明，放到它说明的那一步后面。对不上的先按发图顺序放，在选主题那条消息里一起问。看不了图片时也按发图顺序放，在选主题那条消息里请用户每张说一句。

### 3. 写成文字稿

- **只排版**：照 `references/draft-format.md` 把原文整理成文字稿（`.md`）加标记，原文的意思、数字、语气都不动。
- **写稿再排**：先照 `references/writing.md` 写，再加标记。缺的事实写成「【待补：……】」，不要编。
- 两种都照 `references/recipes.md` 决定用哪些块（步骤、踩坑、原话、对比、金句）。

### 4. 选主题（停）

- 用户点了名，或者说“你定”“直接排”：跳过这一步（说“你定”就照 `references/themes.md` 的“推荐栏目”选一套）。
- 否则在工作文件夹跑 `python3 scripts/render.py --pick`，出六套缩略图「选主题.png」（没装 playwright 就只有「选主题.html」），发一条消息，然后**停下来等用户回**：
  1. 六套缩略图；
  2. 推荐哪套、一句理由；
  3. 写稿再排时：稿子全文和“请你核对”（哪些是按截图推断的、哪些过渡是你补写的、哪些「【待补】」要补）；
  4. 截图对不上的、要不要加署名（第一次用时）；
  5. 最后一句“你可以这样回：用 3，第二段那个数字改成……”。
- 用户想拿自己这篇比一比，跑 `--theme all`，把六套对比页一起发过去。

### 5. 排版

用户回了编号（和要改的地方），先改好文字稿，再排：

```
python3 scripts/render.py 文字稿.md --theme 3
```

### 6. 看结果

- **必须改**：改文字稿，重跑，直到清零。
- **排版提示**：能改就改。最常见的是“第 N 段没标关键词”，补上再跑一遍。
- 能打开预览页就自己看一眼。

### 7. 交付

照专家守则第九节，一条消息说清：

1. 打开「文字稿_主题_预览.html」，点「复制（带截图）」，去公众号后台新建图文，在正文里粘贴；截图没跟着进去，就点「复制（截图留空位）」重新粘，再照图号补图。
2. 用的哪套主题；想换回编号，几秒钟重排。
3. 还剩哪些「【待补】」没补；只排版时，补了哪些小标题、拆了哪些段。
4. 还缺的截图、要打码的地方。可以顺手给 3 个标题备选、一句摘要。

用户要改就改文字稿重跑，几秒钟一版。

## 红线

- 没有的成果不写成有；不编数字，截图说明只写截图里看得到的东西。
- 价格、承诺、要担责任的话，留给用户自己定，写成「【待补：……】」。
- 只排版时不改原文；补的小标题、拆的段落、调的顺序，交付时说清楚。
- 截图里有手机号、客户名、订单号、内部数据，提醒用户先打码；公不公开由用户决定。

## 文件

| 文件 | 干什么用 |
|---|---|
| `settings.md` | 默认设置和设置文件的写法（用户自己的设置放工作文件夹的「公众号设置.md」） |
| `references/专家守则.md` | 分线、回复格式、什么时候停、硬规矩、出问题怎么办 |
| `references/themes.md` | 六套主题和推荐栏目 |
| `references/writing.md` | 写稿再排时怎么写 |
| `references/draft-format.md` | 文字稿怎么写、怎么标记 |
| `references/screenshots.md` | 截图怎么编号、怎么对位 |
| `references/recipes.md` | 不同栏目用哪些块 |
| `references/add-theme.md` | 加新主题 |
| `scripts/render.py` | 排版、出选主题缩略图 |
| `scripts/check.py` | 公众号格式检查（排版时自动跑） |
| `scripts/themes.py` | 六套主题的长相 |
| `assets/sample.md` | 样稿，所有标记的用法都在里面 |
