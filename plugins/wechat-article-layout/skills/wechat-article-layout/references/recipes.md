# 不同栏目用哪些块

同一类文章每次用同一套结构，读者看多了会认得出来。下面是推荐的组合；用户的稿子不是这个结构就按稿子来，不要硬套。
用户自己的栏目名不一样没关系，按意思对：讲软件怎么用的就是“软件实操”，讲自己翻车经历的就是“踩坑实录”。

通用规矩：

- 除了段落、章节、截图，**一篇里用的块最多 3 种**（比如步骤 + 踩坑 + 金句）。
- 金句全文 1 到 2 句；加粗全文不超过 5 处。
- 结尾固定：最后一章叫“写在最后”，文章信息里写好“互动”。

## 软件实操（操作教程）→ 推荐 1 手册蓝

```
开场一两段：这篇解决什么问题，为什么要学
## 第一块操作
  ### 步骤 + 截图（一步一图）
  代码框：要照着发给 AI 的话、网址
  :::坑  这一块最容易出错的地方
## 第二块操作 ……
## 写在最后：一句话收住，往上拔一层
```

文章信息里写“信息: 耗时=… | 难度=… | 适合=…”，读者一眼知道要花多久。

## 踩坑实录 → 推荐 3 老板笔记

```
:::原话 说话的人   开头用真实原话
讲这个人、这件事
## 坑在哪
## 后来怎么改的（有步骤就用 ###）
> 金句：从原文里挑一句“是A，不是B”
## 写在最后
```

## 问答 → 推荐 2 黑金

```
:::原话 提问的人   把问题原样放出来
一两段先给结论
## 为什么这么说
## 具体怎么做（有步骤就用 ###，有截图就配上）
> 金句
## 写在最后
```

## 实测对比（同一个活儿，前后对比）→ 推荐 4 汇报青

```
副标题写结论（汇报青会放进“先说结论”色块）
:::对比 之前 | 之后   只写用户给过的数字和事实
## 怎么做的（步骤 + 截图）
## 还没解决的   做得不好的地方照实写
## 写在最后
```

对比表里**不写没验证过的数字**。用户没给数字，就写做法上的区别。

## 短观点、随笔 → 推荐 5 黑白极简

段落为主，一两句金句，不用步骤和截图。

## 清单、工具盘点 → 推荐 6 活力橙

```
## 每个工具或每条清单一章
  #### 小标题：适合谁 / 怎么用 / 要注意
  截图
编号清单收尾
```
