# 选题雷达与评分

用于“今天拍什么”“这个热点要不要跟”“从业务真事里挖选题”“建选题池和内容日历”。沿用当前老板的定位档案、内容栏目和已采纳的写稿规则；没有定位档案且用户不知道拍什么时，先按[第一次使用](first-use-positioning.md)出定位，不直接给热点清单。只要选题、不要成稿时，不顺手写完整文案。

## 1. 同时看三类信号

1. **老板自己想讲的方向**：最近有感触的事、正在做的决定、准备推进的计划。
2. **真实业务素材**：客户原话和常见问题、工作现场、交付过程、案例前后变化、本人踩过的坑。
3. **公开热点和行业变化**：当前可用的网页搜索或热点工具（如 TrendRadar、Agent Reach）实际检索，附来源和日期；工具不可用就如实说明，不凭记忆冒充最新。

热点只是信号。先判断它和老板定位、目标客户、手上真实素材有没有关系；没有真实经历时，可以做观点解读，但不能包装成亲历故事。

## 2. 评分

| 维度 | 分值 |
|---|---:|
| 是否击中目标客户的真实问题 | 30 |
| 是否符合老板长期定位和当前经营目标 | 20 |
| 是否有真实案例、现场或可靠资料 | 20 |
| 是否能表达鲜明且有边界的判断 | 20 |
| 是否有时效性或持续价值 | 10 |

- 80分以上：近期优先拍。
- 70到79分：进入储备，补素材后再拍。
- 70分以下：暂不进入拍摄队列。

分数是排序工具，不是播放预测。分数相近时，优先老板亲身经历过、能拿出现场或实物的那条。

## 3. 每个候选写清

- 一句话选题和可能的封面方向
- 目标客户的哪个问题，最好附一句客户原话
- 这位老板独有的角度，来自哪段语料、哪个故事卡或哪次现场
- 还需要补的事实、案例或画面
- 时效与风险（行业资质、夸大宣传、客户隐私、平台规则）
- 评分和建议形式：口播、现场Vlog、录屏演示或混合

## 4. 输出

按“现在就拍／储备／不建议拍”三组给出，每组写原因。做月度选题或内容日历时，先对齐[阶段内容规划](report-and-services.md)里的栏目比例和数量，再排序；数量依据服务、预算和素材，不套示例数字。

用户选定后再写稿；写稿时开头、结构与封面按[开头、结构与封面配合](opening-and-structure.md)检查。复盘发现某类选题持续有效或无效，按[客户建议与沿用](client-learning.md)记录，由用户决定是否写进该客户的选题规则。
