# 截图、视频与下一轮写稿复盘

用于视频号、抖音的单条或批量短视频复盘；用户提供截图、导出表或视频即可进入，不强制重做全案。沿用客户档案、内容目标和已确认信息，配合[平台核查](platform-research.md)、[建议采纳与沿用](client-learning.md)及[复盘工作表](../assets/video-review-workbook.md)。小红书及直播另按实际界面和业务适配，不能直接套用本篇字段或阈值。

## 1. 接收与核对截图

- 先识别客户、平台、账号、作品编号或标题、发布时间、视频时长、统计截至时间及区间、是否投放。已有信息不重复问。影响结论的缺口集中列出，同时完成可判断部分。
- 实际查看上传图片；本地图片用可用图片查看工具。按截图编号和区域记录字段原名、显示值、单位、时间口径和识读状态。模糊、裁切或未显示写“不清楚／未提供”，不能当成零。需要时请用户补清晰局部；不得根据常识补齐数字。
- 区分播放次数与观看人数、曝光与播放、点赞与推荐、总量与单条、累计与单日、人数与次数、自然与付费；按当前后台标签判断，不擅自统一成另一平台字段。
- 同一作品在不同时间的累计截图形成时间序列，不能直接相加；同一时点重复截图去重。差值仅在相同口径下计算，下降先排查修正、去重或统计区间变化。
- “1.2万”等保留原始显示并注明约数；比例的小数位和单位以截图为准。计算值写出分子、分母、公式与取数位置；分母缺失、为零或不可比时不计算。平台已给出的比例优先保留其口径。
- 留存曲线需确认横纵坐标、视频总时长与作品对应关系。图上估读标“约”，不编造精确秒数或百分比。只有平均观看时长不能倒推每秒留存；平均观看时长除以视频时长也不等于完播率。
- 用户通常只需上传截图和对应视频，其他字段尽量从材料读取。没有视频时仍交付数据部分，再说明哪些定位和改稿暂缺依据，不能假称已审片。

## 2. 比较与定位

先判断视频任务：触达新受众、专业信任、咨询获客、招聘或其他。主要指标围绕任务选择，播放量不是唯一结果。参考同一账号、同平台、相近选题任务、形式、时长、发布后观察窗口及流量来源的作品。能拿到多条时看常态、中位数及波动，不以最好的一条充当必达基线。样本少、未到观察窗口或混合投放时降低结论确定性。

下表是排查路线，不是“一个指标对应一个原因”的诊断公式。只有后台实际提供的字段才进入分析。

| 观察方向 | 需要结合的证据 | 可检验的内容问题与下一步 |
|---|---|---|
| 曝光与进入 | 流量来源、发布时间、封面标题、真实可见的曝光或进入字段 | 区分搜索、主页点击与直接播放入口；只有存在可比曝光分母时讨论点击率，不把低播放直接归因于封面或限流 |
| 开头留人 | 开头实际台词、首帧、声音和该时段留存 | 目标观众能否迅速听懂与自己有关的事；检查无关铺垫、承诺不明、收音问题；不预设所有视频必须同一秒数完成钩子；可参照[开头、结构与封面配合](opening-and-structure.md)的检查项形成假设 |
| 中段理解 | 留存下降区间对应台词、画面、停顿及信息变化 | 检查重复、跳跃、术语、举例缺失、画面不支持口述；流失与段落重合只能形成假设 |
| 看完与互动 | 时长、平均观看、完播、评论内容、分享或收藏等 | 看是否兑现开头、给到具体价值，分清评论争议与目标客户反馈；不默认越短越好，也不为提高完播删掉必要事实 |
| 关注与咨询 | 可追踪的关注、主页访问、咨询内容与承接入口 | 检查服务对象是否清楚、是否有下一步理由、入口是否真实可用；低咨询还可能涉及需求、产品和接待，不能只怪文案 |
| 经营结果 | 去重有效需求、来源依据、报价与成交跟进、采购周期 | 不把评论人数、意向或截图营收当新增成交；依业务实际路径分析，未能归因写未知 |

视频号按当前截图区分推荐、朋友、关注、搜索等实际可见入口；抖音按推荐、搜索、主页等实际可见入口及自然／投放拆分。入口未显示就标未知，不引用所谓全平台固定占比。低播放不等于受处罚；有账号或作品异常提示才结合当前官方说明核查，不猜“账号权重分”。

## 3. 将问题定位到视频

实际读取可用视频、音频或字幕，说明已看／已听范围。长片分段查看时交代覆盖范围；仅有抽帧不能评判语气和停顿，只有逐字稿不能评判画面、收音与镜头表现。工具不可用时不虚称已播放。

将可疑区间与前后语境对照，记录“实际时间段或原稿段落—原话／可见画面—数据现象—原因假设—其他可能原因—建议动作”。无真实时间码用段落号；曲线只能估读时使用区间。优先找少数最值得改的地方，也保留已经有效的部分。

结论标为“已观察到”“较强假设”“证据不足”，并写理由；不捏造把握度百分比。需要识别本人语气时以实际音视频和语料为依据，不凭后台数据诊断创始人性格。

## 4. 每次交付的内容

先给主要结论和优先动作，再给以下配套材料，篇幅随材料多少调整：

1. 数据核对表：截图来源、字段和值、口径、计算或读取限制。
2. 问题定位表：视频位置、可见证据、假设及替代解释、修改动作。
3. 改稿：提供修改理由与可直接使用的完整新稿，保留人物事实、本人语言及未改部分；只有某段资料时明确为局部改稿或待补骨架，不能编造全文。只有数据没有内容时，先给修改方向和补件项。
4. 与改稿同步的[现场提问或提示卡](on-set-interview.md)：逐段对应；镜头或剪辑建议区分“可用现有素材重剪”和“需要补拍”。交付改稿不等于已经剪出新片。
5. 下一条验证卡：提出明确假设、主要改变的一个因素（资源或任务需要多项一起改时如实注明无法单独归因）、尽量保持的条件、主指标与护栏指标、比较对象、观察窗口和回看条件。24小时或7天等只能作为项目约定示例，不称官方推流周期；样本有限不能承诺显著提升。
6. 建议采纳清单：给每条建议编号，列作用、适用范围和待采纳状态，让用户可直接回复“采纳第几条”或“仅这次试用”。即使原因尚未证实，也可以明确作为试验建议交付。
7. 本次来源日期、官方依据、运营经验出处与未核验范围；只列真正影响判断的依据，不堆链接。

## 5. 数据验证与下一轮

复盘先读该客户上轮建议、实施记录和本轮结果，分清“建议提出”“用户采纳”“实际执行”“结果观察”。执行后没效果不自动判建议无效，先核对执行程度、窗口、流量与内容条件；效果改善也不单凭前后两条认定因果。按[采纳规则](client-learning.md)更新验证状态，并将已采纳且适用的规则用于后续新稿与提问卡。

## 交付验收

检查每个数字是否能回到截图或导出数据，每个视频位置是否有实际内容依据，每项原因是否与假设区分，每条改稿是否有提问卡，每条实验是否可回看；未知与零、采用与有效、稿件与成片不能混写。不得用行业通用分数代替用户的数据，也不得承诺精准预测播放或成交。
