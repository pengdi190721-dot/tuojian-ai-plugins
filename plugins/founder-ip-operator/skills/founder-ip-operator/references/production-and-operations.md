# 拍摄与运营执行

本技能只出纯实拍的拍摄方案（现场怎么问、要准备什么、镜头顺序），不做剪辑包装、封面图和AI生成画面。老板要剪辑、做封面或用AI补画面时，用他自己已有的工具或交给同事，本技能可以说清这条视频要什么效果，不代做、不出成品。

## 表达方式先于特效

先看老板在哪种状态下最自然：拿着东西讲、边干活边讲、旁边有人陪聊，还是直接对着镜头。试拍时记下为什么重录、语速、停顿和老板自己满不满意，调整提问方式，不逼他背稿。没有原始视频时只能给拍法建议，不说已经看过他镜头前的表现。

时长由要讲的事和自然语速决定。讲一个产品可以先试短一点，讲经营故事要把前因后果留住；任何时长只是试的起点，不是平台规定。

## 现场问答拍摄

每次写稿或改稿，按[现场提问与提示卡](on-set-interview.md)逐段配好主问题、回答要点和备用追问；老板一个人录时，给自问自答的问题和关键词提示。改稿时卡片一起改，不拿首访问卷充数。试拍时看回答能不能单独成句、该说的有没有说到；回答和稿子对不上时，先核实再改稿。

## 纯实拍怎么拍

本人讲述，加上现在的环境，再加上核实过的旧物件和老照片。用现在的镜头讲过去的事可以，但不能假装是当年拍的录像。

给拍摄方案时列清：

- 每段说什么、在哪拍、手里拿什么、拍几个镜头
- 要提前准备的东西：物件、屏幕画面、数字、人、地方
- 收音和光线：离嘴近一点、别背着窗户
- 补充画面（空镜）：车间、产品、手在操作这类不拍脸的画面，各拍几秒备用

不得拿任何画面去证明不存在的客户评价、订单、工资单或结果。

用户给参考视频时，先实际读取，记下看了哪些；可以学结构、节奏和衔接，不照搬别人的故事和身份。读不了就如实说，不凭文件名"看懂"视频。拆参考视频按[对标视频拆解改写](benchmark-remix.md)做。

## 拍完到发布

选题和事实整理 → 拍摄准备 → 试拍和现场拍摄 → 老板或同事自己剪 → 核对事实和是不是像本人 → 发布前打分 → 发布。已经确认过的沿用；只有新增事实、公开范围或要花钱时再确认，不设没意义的逐步审批。

发布前按[成片评分教练](pre-publish-review.md)打分。拿到成片时，实际打开看：能不能播、时长、画面、声音、字幕、标题和内容对不对得上。

发布前核对：事实和资料、客户和人物能公开到哪一步、产品或行业说法有没有依据、是否需要标注演绎或广告、音乐能不能用、留的咨询方式能不能联系上。具体以当时的平台规则为准，不教怎么钻审核空子。

## 三个平台改版

平台选择、同一个题改成三个平台的版本、发布前复核，按[三平台执行流程](platform-distribution-and-rules.md)。先想清楚客户是谁、从哪找到你，再定每个平台的标题和剪法。

同一件事、同一个老板的说话方式保持一致，只调整开头、长短、标题、信息顺序和留的联系方式。平台建议是要验证的假设；不能把一个老板在三个平台写成三种性格。

一个题可以改出几个版本，但每改一版、剪一版、发一版都算工作量。"一份内容计划"不等于"三个平台都帮你运营"。

## 运营与复盘

收到后台截图、导出数据和视频时，按[视频数据复盘](video-performance-review.md)核对、找问题、改稿、安排下一条怎么验证，每条附提问卡。老板采纳后，按[客户规则](client-learning.md)保存，以后写稿接着用；采纳了不等于已经证明有效。

按老板的委托记录每条的状态：待拍、拍摄中、待审、已交付、已发布。已发布要有链接或后台截图，存了草稿不算发布。

拿客户提问当下一轮选题时，去掉无关的隐私，确认能公开。没有新提问就用以前的常见问题，不能说"很多客户都在问"。不编评论、好评和互动。

比较数据时，同一个平台、差不多的形式、看的时间段要一致；没花钱的流量和花钱买的流量分开看。不编后台没有的指标和算法分数。按[经营诊断](business-diagnosis.md)分清"看到了什么、猜是什么原因、核实了没有"，结合客户反馈、成交周期、交付成本、老板时间和实际分工，更新30天要先做的事、谁负责、看什么数、什么时候回头看；证据不够先攒基础数据，不把播放或营业额的变化直接算到内容头上。
