# 复盘建议的采纳、保存与后续沿用

用于用户要求“采纳后，以后的新文案也按这个形式”。这是一位创始人、一组账号的项目规则，不是将个案写成所有客户通用方法。与[视频复盘](video-performance-review.md)、[本人口语档案](transcript-and-voice.md)配合。

## 记录在哪里

沿用当前客户资料目录，默认在工作区“客户资料／客户代号／”保存“复盘建议台账.md”和“写稿规则.md”；小项目可合并到已有档案，保留可追踪的采纳记录。原始截图、视频及台账不进入技能安装目录、示例、公开资料库或分享包，不写入系统记忆目录。用户授权在本项目保存与沿用建议时即可落盘，无须反复询问文件写入权限。

客户身份明确就直接使用已有目录；多位创始人或账号无法区分时只澄清必要归属。没有持久存储能力时交付可复制规则卡并说明需要下次带回，不能承诺永久记忆。

## 两个状态分别记录

- 采纳状态：待采纳／已采纳／仅本次试用／未采纳／已撤回。
- 效果状态：未执行／执行中／样本不足／在所列范围观察到改善／未观察到改善／需调整。

记录建议编号、提出日期、具体写法、依据与来源、适用创始人／账号／平台／栏目／目标、排除条件、用户确认原话或消息位置与日期、生效范围、执行作品及验证结果。只有实际反馈支持才能更新效果状态。

“采纳第2、3条”“以后按这个写”是授权依据；“先试这一条”仅本次使用；“看到了”“再看看”或未回复不等于采纳。用户明确采纳后，当轮更新台账和写稿规则，并简短说明后续沿用范围，不再要求逐条重复确认。首次明确采纳无需等多轮数据验证，标为已采纳、效果待验证即可。

## 每次写新文案前

1. 识别当前客户、平台、内容目标及栏目，读取其最新“写稿规则”和人物表达档案。可用工作区有平台更新索引时，同时检查其中与本任务有关的新依据。
2. 只应用已采纳且范围匹配的建议，例如某平台案例栏目采用“先讲现场问题，再展示过程”；不能扩展为所有平台、所有故事都必须这种开头。仅本次试用的建议不默认续用。
3. 当前用户新要求优先于旧规则；明确撤回立即停止，保留历史。新官方规则若使旧方法不适用，指出来源、暂不用于当前任务并给兼容改法；不悄悄扩大或覆盖客户偏好。
4. 事实与本人表达优先保真，允许不同主题自然变化；不得为套新结构补造经历或改成另一个人的口气。改稿后的现场提问或提示卡同步采用结构。
5. 交付末尾简短注明本次沿用的建议编号或形式及未适用的必要原因，不把整份内部台账塞给用户。

新对话中按当前客户目录恢复规则。只有多个目录均可能属于当前客户且无法确定时才询问；找不到已采纳记录则说清范围，不假称记得所有过去建议。

## 定期研究与客户规则的关系

定期联网只更新官方资料和候选经验。没有客户采纳就不加入其长期写稿规则；别的客户成功也不自动迁移。每次复盘可以提出有来源的新实验，用户采纳后才成为相应客户后续创作依据。归档的是规则与证据，不能上传客户截图、手机号或咨询原话到外部搜索服务。
