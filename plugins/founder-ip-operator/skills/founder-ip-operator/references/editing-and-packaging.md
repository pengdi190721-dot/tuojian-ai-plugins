# 剪辑与包装

用于用户上传口播或Vlog视频、音频，要粗剪、删口误、做字幕、重点大字、信息卡、动效、镜头排序或剪辑清单。只写稿时不走这一步。封面走[九式封面](cover-design.md)；发布前打分走[成片评分教练](pre-publish-review.md)。

## 先剪内容，再做包装

1. 按[视频解析](video-analysis.md)先读素材：时长、尺寸、声音、画面、转写、关键画面和时间线。不要让用户处理技术参数。
2. 内容粗剪和视觉包装分开做，先保证这条讲的事成立。
3. 口播可以机械删除明显口误和无意义长停顿；情绪停顿、真实转折和可能改变原意的片段，必须人工确认。
4. Vlog先整理故事线和素材证据，再剪时间线。
5. 任何生成、转码或导出，都要检查实际文件、尺寸、时长和能不能播放。

画面再华丽也补不了故事和事实的问题。

## 可以自动处理

- 转写、明显口误和无意义长空白
- 字幕草稿、重点词和基础版式
- 素材清单、时间码和粗剪建议
- 分辨率、时长、格式和文件存在性检查

## 必须人工判断

- 开头几秒是否成立
- 情绪停顿和人物反应是否保留
- 删掉的内容是否改变原意
- Vlog的故事主线和真实转折
- 客户、公司、现场和隐私能否公开
- 成片是否像本人，而不是像模板

## 工具

- FFmpeg 可用时：素材检查、转码、抽音频等机械处理，不代替内容判断。
- HyperFrames 等程序化包装工具可用时：字幕、重点提示、信息卡和确定性动效。
- 网页渲染加 FFmpeg 也能做逐帧透明字幕层和音效合成，适合“讲到重点出大字”这类需求。
- 工具都不可用时：给可执行的剪辑清单，或用当前环境已有能力完成可验证的部分。

## 重点大字与音效

- 先按转写的逐字时间找出重点句，一处一个重点，不堆满全片。
- 每处重新看人脸和原字幕的位置：说话段放在下巴和字幕之间，录屏段放在不挡操作界面的位置；该让观众看清画面的地方留空。
- 大字用词和本人说的一致；本人口误或原字幕写错的词，大字用正确说法，并提醒用户自己改原字幕。
- 音效跟着出字节奏，音量压在人声下面，合成后检查有没有爆音。
- 交付时把合好的成片、单独的大字层和单独的音效轨都给，方便用户自己微调。

## 交给剪映的素材

只交素材、由老板或剪辑人员自己放进剪映时：

- 先给素材建议供选择；真实录屏和实拍优先，卡片只补纯口播长段。
- 静态卡用整屏竖版透明底图片。
- 动画优先给透明底视频，同时给绿幕版本备用：剪映可能不识别透明通道，导入后会变黑底。
- 绿幕层只用纯绿和不透明的图像，边缘不留半透明像素，否则抠像时字边会闪绿；能直接给合好的成片时，优先给成片，不需要抠像就不会闪。
- 整屏插片放画中画轨道，避免主轨覆盖原声；附放置时间清单。
- 答应给工程文件，就验证可编辑工程确实交付了。只有策划稿、素材清单或排队任务时，不能称成片完成。

## 交付

成片同时附人工复核清单，不把自动结果称为最终成片。检查视频实际存在、能播放、时长、画面、收音、字幕、标题与内容一致；按条列出改了什么、哪些需要本人确认。
