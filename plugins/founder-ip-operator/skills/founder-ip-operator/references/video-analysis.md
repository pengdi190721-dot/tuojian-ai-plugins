# 视频解析

本篇只供技能内部路由使用。对用户统一说“正在解析视频”，不要让用户选择转写模型、抽帧密度、识别语言或命令参数。对标拆解、成片评分、口播体检和视频复盘都靠这一步拿到转写、关键画面和时间线。

## 输入优先级

1. 本人原始视频或清晰导出文件，使用绝对路径。要看画面、审成片，只能靠这一种。
2. 视频链接（抖音、小红书、B站、公众号、得到App，含整段分享口令）：一律存进得到大脑读文字稿，免费账号就行，按[读视频链接：得到大脑](knowledge-base-getnote.md)走。只有文字、没有画面，分析时注明。
3. 视频号链接：得到大脑读不了，请用户录屏或下载后发视频文件。
4. 转写、截图或压缩视频只能做降级分析，必须说明缺了什么。

聊天软件压缩可能改变清晰度、音量和字幕可读性；评分时注明收到的是原片还是压缩版。

## 内部执行顺序

1. 以插件方式安装时，优先调用插件自带的 `video-analyzer` 工具：完整审片用 `analyze_video` 的详细模式；只缺某个时间点的证据时用 `analyze_moment` 或 `get_frame_at`。
2. 工具返回的转写为空，但本地视频有声音时，运行本技能的 `scripts/analyze_video.py` 补做本地转写并合并结果。
3. 以独立技能方式安装（没有 `video-analyzer` 工具），但本机有 Python、Node.js 22.12 以上和 npx 时，直接运行同一脚本完成本地解析：

   ```bash
   python3 scripts/analyze_video.py 视频绝对路径 --detail standard --json-output 输出路径.json
   ```

4. 仍不可用时，用当前环境已有的媒体读取、FFmpeg、转写或看图能力。
5. 最后才降级为用户提供的转写和截图。降级分析不能称为完整审片。

默认使用本地语音识别，不向用户要任何付费接口密钥。第一次转写会按需联网下载本地识别组件，以后复用缓存，需要提前告诉用户可能要等一会儿。不得为了方便把视频自动发到未说明的第三方视频理解服务。环境是否就绪用[环境体检](environment-check.md)查。

## 每次记录完整度

- 是否取得完整或分段转写
- 是否取得关键画面和时间码
- 是否取得时长、尺寸、编码和音轨信息
- 是否有下载失败、无字幕、静音、画面缺失或识别不确定

## 发来链接时

视频链接只走得到大脑，不再自己下载，也不让用户去改代理、装视频号下载器。具体步骤见[读视频链接：得到大脑](knowledge-base-getnote.md)：

- **得到大脑已连上**：存链接、等笔记出来、读全文逐字稿，再接着做拆解或看行情。对用户只说“正在读这条视频”。
- **还没连上（多半是第一次用）**：直接把注册登录链接给他，告诉他免费就能用，弄好了再带他授权。不先讲别的办法，不推会员。
- **视频号链接，或者命令行连不上**：视频号照实说读不了，请他发视频文件；命令行连不上就请他在得到大脑App里存好链接、把文字稿复制过来。发视频文件时，抖音里保存到相册，或者用手机自带录屏。录屏会带进状态栏和通知，解析时注明“录屏版”。
- **要看画面**（镜头、字幕、表情、成片打分）：得到大脑只有文字，请他发视频文件，按上面的顺序在本地读。

读到的别人的视频只用于这次拆解学习，不转发、不搬运；未经明确授权不得读取浏览器凭据。

## 解析之后：说得有没有劲

拿到转写后，如果任务是审自己的成片、判断口播状态，接着跑[口播体检](voice-delivery-check.md)：

```bash
python3 scripts/voice_delivery.py 视频.mp4 --transcript 刚拿到的转写.json
```

它用 ffmpeg 算声音大小、停顿和语速，出一份文字报告（装了 matplotlib 还会出一张曲线图），把“感觉不对”定位到具体第几秒。**它不判断情绪**：情绪和表演只有本人与目标观众能给，不要越界下结论。

## 证据边界

- 抽帧只能证明抽到的那几个时刻，不能断言整条视频都如此。
- 自动转写里的专有名词、数字和人名必须回听，或标注不确定。
- 只描述可观察的语速、停顿、镜头朝向、表情和姿态，不做心理诊断。
- 对标视频只提取结构和表现规律，不输出大段原文，不帮人冒充原作者。
