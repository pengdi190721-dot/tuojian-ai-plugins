# 口播与Vlog结构

写新稿时可选用的骨架。它们只是起点：客户已采纳的写稿规则、本人改稿和本人习惯的讲述顺序优先；不能为了套骨架补造经历或改掉老板原话。开头和整体节奏仍按[开头、结构与封面配合](opening-and-structure.md)检查，本人语言按[逐字稿与表达规范](transcript-and-voice.md)保真。

## 写稿前

优先使用已有的选题卡、研究简报、人物与表达档案和真实素材。缺少时可以继续写，但标明假设，不补造经历、客户评价或效果数据。

## 口播骨架

```text
现实冲突：多数人以为……但我看到的是……
真实场景：最近在……发生了……
个人判断：所以我的判断是……
原因解释：真正卡住的是……
可执行动作：如果你正在面对这件事，先做……
边界：这不代表……也不能仅凭……判断……
收尾：回到老板的长期计划或系列进展
```

## Vlog骨架

```text
任务与期待
→ 进入现场
→ 遇到阻力或意外
→ 判断发生变化
→ 采取一个真实动作
→ 得到阶段性结果
→ 留下仍未解决的问题
```

Vlog保留现场转折、人物反应和真实的不确定；不把演示写成已经完整落地，不把阶段性验证写成长期效果。

## 视频号与小红书改写要点

| 视频号 | 小红书 |
|---|---|
| 真实经历和信任优先 | 问题、收益和搜索词优先 |
| 可以保留完整转折 | 提高前段信息密度 |
| 开头像真人聊天 | 标题先说清冲突或价值 |
| 收尾强化长期计划 | 收尾引导收藏或讨论 |

核心观点和素材可以共用，但至少重做标题、前两句、字幕重点和收尾。抖音版本和三平台取舍按[三平台执行流程](platform-distribution-and-rules.md)，平台说法都是工作假设，需要数据验证。

## 一条稿子交付什么

用户要可拍稿时，至少交付：

1. 2到3个开头备选（问题＋答案、本人习惯说法、更强冲突），写各自风险。
2. 主稿，标预计时长；按本人实测语速估算，没有实测就注明估算。
3. 第1秒画面和每段的镜头或素材提示。
4. 字幕重点：哪几句要做成大字。
5. 剪辑备注：哪里留停顿、哪里插录屏或实物。
6. [现场提问或提示卡](on-set-interview.md)，逐段对应。
7. 发布包装：标题、简介、话题和封面字，按[九式封面](cover-design.md)出封面时封面字和开头一起定。

用户只要简短版时，先交可直接拍的那一版。要拍时只要“纯口播稿”的，只留要念的话，去掉时间、画面和标记。
