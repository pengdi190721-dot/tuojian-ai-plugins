# 真实故事短剧化

把真实素材变成有戏的故事，但不把戏剧化变成造谣、硬造反转或消费当事人。

## 默认交付

这是一个有确认关卡的分阶段工作流。收到故事、采访录音或逐字稿后，不能直接生成完整短剧方案。

用户未指定时，默认：

- 单集、竖屏、60—90秒；
- 中等戏剧化，人物与机构匿名；
- 先理解材料并等待用户确认故事大意和主题；
- 确认后给出三个机制不同的方向，选出推荐方向并继续写完整稿；
- 先用GPT Image 2生成并确认逐镜图片，再为已确认图片定稿Seedance图生视频提示词；
- 交付可编辑文本，不宣称已经拍摄、生成或发布。

## 五条硬规则

1. **先理解，再确认，再写戏。** 读取[素材理解与主题确认](references/material-understanding-and-confirmation.md)。没有用户对故事大意和主题的明确确认，不进入完整短剧方案。
2. **先分事实，再写戏。** 写作前读取[事实与改编边界](references/truth-contract.md)，区分已核实事实、当事人记忆或感受、转述或争议信息、可创作空白。
3. **冲突从真实压力中长出来。** 使用目标冲突、制度限制、关系边界、时间压力、艰难选择和选择代价；不得为了“有戏”凭空制造坏人、秘密或恶意动机。
4. **反转不是必选项。** 没有真实反转时，可以通过信息重排、观众理解变化、人物选择变义或情绪回收形成转折；不得硬造身份、罪行、背叛、疾病、债务或其他可核验事件。
5. **所有改动可追溯。** 压缩、调序、合并人物、重构对白、补过场和虚构演绎都写入改编台账；不能把重构对白冒充采访原话或逐字原话。

## 工作流

### 0. 接收并理解原始材料

保留用户原始故事、录音和逐字稿，不覆盖原文。

- 用户提供文字时，区分叙述者亲历、主观感受、转述和未知；
- 用户提供录音时，先使用当前环境可用的转写或音频理解能力；没有可用能力时，明确请求逐字稿，不假装听过；
- 标记说话人、关键时间点和低置信内容；听不清的人名、金额、日期和关键否定词必须列为待确认；
- 只有能从录音或逐字稿直接定位的句子，才能标为采访原话。

### 1. 故事理解与主题确认关卡

第一轮只输出：

1. 我理解的故事大意；
2. 主人公、目标、压力、关键选择、结果和余波；
3. 已确认事实、当事人感受、转述争议和信息缺口；
4. 两到三个主题候选及各自会突出什么；
5. 推荐主题及理由；
6. 一句明确确认请求。

状态标记为“待主题确认”。此阶段不输出三个戏剧化方向、完整剧本、分镜、图片提示词或视频提示词。

用户可以确认、纠正故事大意、选择主题或重新定义主题。只有出现“确认”“就是这个意思”“选方向二”“按这个主题继续”等明确答复后，才进入下一阶段。主题分叉会改变故事含义时，每次只问一个问题。

### 2. 建立事实底稿

列出：

- 不可改变的事实、人物关系、关键选择和结局含义；
- 当事人的主观感受与记忆；
- 尚未证实、存在争议或仅为转述的信息；
- 用户明确允许压缩、合并、调序或重构的范围；
- 需要匿名、模糊或取得确认的身份信息。

未得到用户确认时，不保留真实姓名、公司名、精确地址、联系方式和足以单独识别普通人的组合信息。

### 3. 找到真正的戏剧发动机

读取[戏剧化开发](references/dramatic-development.md)。先判断原故事为什么平，再寻找最值得进入的时刻：人物原有做法开始付出代价、必须作选择，或一个旧事实改变当前关系的地方。

三个候选方向必须改变冲突机制，例如：

- 人物目标与制度或现实限制冲突；
- 两个都可以理解的关系目标冲突；
- 人物旧信念与眼前选择冲突。

不能只换标题、职业、语气或把同一场争吵写得更大声。

### 4. 写成可拍剧本与逐镜执行稿

读取[脚本与分镜格式](references/script-and-shot-format.md)。让每场至少改变信息、权力、关系、情绪、风险或物理状态之一，并用以下因果链组织：

```text
因为已有事实 -> 人物采取行动 -> 产生可见结果 -> 形成下一股压力
```

对白用于争取、回避、试探、拒绝、逼迫或重新定义关系，不让所有人物轮流解释背景。分镜和提示词只实现已确认剧本，不新增人物、台词、证据、奇观或结局。

### 5. 先生成图片，再生成视频

读取[GPT Image 2与Seedance图生视频工作流](references/image2-seedance-workflow.md)。

1. 先输出角色视觉锚点和每个镜头可直接复制的GPT Image 2图片提示词；
2. 同时给出图片验收项和Seedance视频提示词草案；
3. 状态标记为“待生图”；
4. 用户生成图片并确认，或上传已确认图片后，先看实际图片中的人物、姿态、构图、物件和运动空间；
5. 再把对应Seedance提示词改成基于该图片的最终可复制版本，状态标记为“视频提示词已定稿”。

没有看见或没有得到用户确认的图片时，不能把Seedance提示词称为最终版。默认一次先定稿一个镜头，用户明确要求批量时才批量处理。

### 6. 交付前静默三检

读取[审查标准](references/review-rubric.md)，依次检查：

1. 事实、采访原话、隐私、名誉和改编台账；
2. 因果、人物选择、冲突升级、局部回报与结尾；
3. 口语、人味、可表演性、GPT Image 2画面可控性和Seedance图生视频连续性。

发现硬伤时直接修正；只有真实剧情分叉、身份暴露或主题变化需要用户决定。不能把脚本、提示词或项目文件说成已经生成的图片或成片。

## 分阶段输出顺序

### 第一阶段：待主题确认

1. 故事大意；
2. 人物与事件链；
3. 事实边界和信息缺口；
4. 两到三个主题候选；
5. 推荐主题；
6. 请用户确认或纠正。

### 第二阶段：主题确认后

1. 一句话判断；
2. 事实底稿；
3. 原故事平铺直叙的原因；
4. 三个戏剧化方向与推荐方向；
5. 故事发动机：人物目标、阻力、选择、代价、转折、局部回报；
6. 完整可拍短剧脚本；
7. 角色一致性卡与逐镜分镜；
8. 角色定妆图和逐镜GPT Image 2图片提示词；
9. 图片验收项与逐镜Seedance视频提示词草案；
10. 原故事与改编内容对照台账；
11. 事实、隐私、名誉、因果和制作审查结论。

### 第三阶段：图片确认后

1. 对实际图片的可用性判断；
2. 必须返修的图片问题；
3. 基于已确认图片的Seedance最终提示词；
4. 建议时长、画幅、清晰度和声音策略；
5. 当前镜头状态。

用户只点名其中一项时，只交付点名范围，但不能跳过故事大意与主题确认关卡。

## 保存到项目时

只有用户要求保存、继续做系列或生成可编辑项目时才落盘。使用技能自带模板，保存为：

```text
真实故事短剧化/<项目名>/
├── 00-原始素材与转写.md
├── 01-故事理解与主题确认.md
├── 02-事实底稿.md
├── 03-改编方案.md
├── 04-短剧脚本.md
├── 05-分镜与图片提示词.md
├── 06-已确认图片与视频提示词.md
├── 07-改编台账.md
└── 08-审查报告.md
```

模板位于 `assets/`：

- `story-intake-template.md`
- `story-confirmation-template.md`
- `adaptation-ledger-template.md`
- `script-package-template.md`
- `review-template.md`

## 边界

- 不替用户确认未经证实的信息，不替当事人授权公开身份。
- 不因为“基于真实故事”就假设所有细节真实；证据不足时保留未知。
- 不擅自把采访中的情绪判断写成客观事实，不把重构对白写成原声原话。
- 不直接生成图片、视频、配音或发布内容；用户另行明确要求后，再调用相应能力。
- 涉及未成年人、医疗健康、亲密关系、犯罪指控、重大财务纠纷或可识别普通人时，默认提高匿名等级；无法安全改编时说明风险并暂停公开版输出。
