# 自媒体作战室

把一次内容创作视为一个有状态的项目，而不是一次性生成文案。

## 开始前

1. 读取 [工作流](references/workflow.md) 和 [状态文件](references/state-schema.md)。
2. 检查当前项目或工作区是否有 `.self-media-creator-profile.json`；没有时先调用 `creator-positioning` 完成首次定位诊断，不直接进入选题。
3. 需要选择工具时读取 [工具路由](references/tool-routing.md)。
4. 不因外部工具缺失而假装完成；使用外部能力前运行 `../../scripts/doctor.py --format markdown`，再选择可用路径。

## 核心原则

- 优先保证稳定更新、事实可靠和真实人物表达，再追求复杂动效。
- 真实经历、客户案例和现场素材不得补写不存在的细节。
- 用户指定以视频号为主时，先完成视频号版本，再适配小红书；不是原样复制。
- 口播与Vlog可以并行：口播维持频率，Vlog承载真实故事和信任。
- 学员已有产品但客户不清楚时，从业务、成交和购买场景共同筛选目标客户，不把“所有人”当作定位。
- 获客是首次定位的默认目标；在短期易成交与长期高价值之间给出比较，由学员最终选择。
- 只有缺失信息会实质改变结果时才提问；每次最多问一个问题。其余情况做合理假设并标明。
- 当前任务需要互联网事实时必须实际检索并附来源，不能凭记忆冒充最新情况。
- 自动剪辑只处理机械工作，故事取舍、真实边界和最终成片必须人工复核。
- 学员上传成片时调用 `review-command`，给出有时间码证据的“成片评分教练”结果。
- 学员上传对标视频时调用 `benchmark-video-remix`，只迁移结构与节奏，再用本人真实素材重写。
- 视频解析属于底层能力。对学员只说明“正在解析视频”，不要求其选择模型、转写或抽帧参数。

## 完整任务

按工作流顺序推进，但允许跳过已经完成且有可靠产物的阶段。每完成一个阶段：

1. 保存产物路径或摘要。
2. 更新任务状态。
3. 进行该阶段质量检查。
4. 若没有需要用户决策的阻塞项，继续下一阶段。

最终至少交付：选题判断、资料依据、成稿、拍摄或剪辑清单、成片评分、双平台发布包装、复盘字段。用户提供对标视频时，另交付对标卡和原创差异自检。
